Coding agents are good at writing code and bad at being trusted with production. InstaCloud is built around that asymmetry: give the agent real infrastructure to work against, keep the blast radius contained, and put a human in front of anything irreversible.

## One branch per task

Give each agent task its own branch: a copy-on-write database with real data, forked storage, and a fresh compute URL. The agent develops and tests against production-shaped infrastructure without touching production. When the task is done, merge what's needed and delete the branch. Branches are capped at 10 per project, which also caps how much an agent fleet can sprawl.

See [branch-per-task](/agents/branch-per-task) for the workflow.

## Credentials stay behind one seam

An agent working on InstaCloud never needs a connection string pasted into its prompt. User secrets live on the platform and reach code through `insta secrets` (writes the branch's `.env`) or `insta run` (injects into a single process, nothing on disk). Provider credentials like the Postgres DSN are held back further: `insta db url` prints one on demand, and deployed services receive them only through explicit bindings. Every one of those reads is governed by the `secrets.read` policy, so you can require approval before an agent touches a credential at all.

The `observe` hook that ships with project setup audits agent tool calls for leaked credentials and records findings to `.insta/audit.jsonl`.

## Humans approve

Destructive and sensitive actions are gated by [policy](/governance/overview). When an agent hits a gated action, the platform returns an approval ID instead of running it. The agent relays one line:

```bash
insta approvals approve <id>
```

Only an admin can approve, grants are single-use, and everything lands in the audit log (`insta events`). Out of the box, deleting a project requires approval; tighten any other action with `insta policy set <action> approve`.

## What ships

Three pieces:

- **The `insta` skill** — teaches terminal agents (Claude Code, Cursor, Codex, and others) the CLI workflow: status, branch, secrets, deploy, and the approval protocol.
- **The MCP server** — `https://mcp.instacloud.com/mcp`, 38 tools covering projects, services, branches, deploys, secrets, logs, metrics, and approvals, for agents that speak MCP rather than a shell.
- **The observe hook** — the per-repo credential audit described above, added when a repo is linked to a project.

## Set up your agent

One command installs the skill and MCP server for every agent on your machine:

```bash
insta setup agent
```

See [Set up your coding agent](/agents/setup) for what it writes and how to verify.
