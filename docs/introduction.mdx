InstaCloud hosts your app's backend — Postgres, object storage, and containers — and lets you clone the whole environment into an isolated branch in seconds. You use it for two things:

- **Deploying an app.** Add a database and a compute service, `insta deploy .`, get a URL. Databases scale to zero and containers sleep when idle — an idle project pays only for the data it stores.
- **Working with coding agents safely.** Give each agent task its own branch — a real database with real data, storage, and a running copy of the app — so agents build against production-shaped infrastructure without ever touching production. Credentials stay on the platform instead of in prompts, and any action you choose can require human approval.

The same `insta` CLI, MCP server, and agent skill drive both the hosted service and [insta-oss](/self-hosting/install), the open-source runtime you can run on your own Docker.

## Start here

Install the CLI:

<CodeGroup>

```bash npx
npx insta@latest setup agent
```

```bash npm
npm install -g insta
```

```bash title="Shell installer (macOS/Linux)"
curl -fsSL https://agents.instacloud.com | sh
```

</CodeGroup>

The npx path installs the CLI and wires up any coding agents on your machine in one command; `npm install -g insta` installs just the CLI. Then, from a directory with a Dockerfile:

```bash
insta login
insta project create my-app
insta services add postgres db
insta services add compute app
insta secrets bind DATABASE_URL postgres/db --to compute/app
insta deploy .
```

That's a running app on its own URL, with its database connection injected. The [quickstart](/quickstart) walks through each step, including creating your first branch; [agent setup](/agents/setup) covers what the agent wiring installs.

```
project = a Postgres database + an S3 bucket + your app containers
branch  = a disposable, fully isolated clone of all three
```

## Hosted or self-hosted

| | InstaCloud | insta-oss |
| --- | --- | --- |
| Where it runs | Managed, multi-region | Your Docker |
| Accounts and billing | Yes | None — single tenant |
| CLI, MCP, skills | Same | Same |
| Cloud-only features | Orgs, GitHub deploys, custom domains, backups, usage | Returns `501` with guidance |

See [CLI & MCP compatibility](/self-hosting/compatibility) for the command-by-command list.
