InstaCloud is a cloud platform built for agents: agents as the primary operator, and agents as the workload.

Traditional devtools were built by humans to serve humans. When the one operating the infrastructure — and increasingly the one running on it — is an agent, that model has to change: environments must be disposable and parallel instead of one shared staging, credentials can't live in prompts, irreversible actions need a human gate rather than a confirmation dialog, and every operation has to be legible to a machine, not a dashboard.

InstaCloud provides the three basic primitives — **database** (real Postgres), **storage** (S3-compatible buckets), and **compute** (microVM containers) — rebuilt on those terms. Every operation is a CLI command and an MCP tool. The whole environment clones into an isolated branch per task. Credentials flow through one seam you can gate, and humans approve what matters. The same `insta` CLI, MCP server, and agent skill drive both the hosted service and [insta-oss](/self-hosting/install), the open-source runtime you can run on your own Docker — and it works just as well when the operator is you.

## Start here

<Steps>
  <Step title="Install the CLI">
    <CodeGroup>

    ```bash npx
    npx insta@latest setup agent
    ```

    ```bash npm
    npm install -g insta
    ```

    ```bash title="Shell installer (macOS/Linux)"
    curl -fsSL https://agents.instacloud.com | sh
    ```

    </CodeGroup>

    The npx path also wires up any coding agents on your machine; npm installs just the CLI.
  </Step>
  <Step title="Deploy your app">
    From a directory with a Dockerfile:

    ```bash
    insta login
    insta project create my-app
    insta services add postgres db
    insta services add compute app
    insta secrets bind DATABASE_URL postgres/db --to compute/app
    insta deploy .
    ```

    That's a running app on its own URL, with its database connection injected.
  </Step>
  <Step title="Keep going">
    The [quickstart](/quickstart) walks through each step, including your first branch; [agent setup](/agents/setup) covers what the agent wiring installs.
  </Step>
</Steps>

## Hosted or self-hosted

| | InstaCloud | insta-oss |
| --- | --- | --- |
| Where it runs | Managed, multi-region | Your Docker |
| Accounts and billing | Yes | None — single tenant |
| CLI, MCP, skills | Same | Same |
| Cloud-only features | Orgs, GitHub deploys, custom domains, backups, usage | Returns `501` with guidance |

See [CLI & MCP compatibility](/self-hosting/compatibility) for the command-by-command list.
