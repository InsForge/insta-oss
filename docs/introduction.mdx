InstaCloud hosts your app's backend — Postgres, object storage, and containers — and clones the whole environment into an isolated branch in seconds. Deploy an app and pay only for what it stores when idle, or give every coding-agent task its own branch of production-shaped infrastructure, with credentials on the platform and human approval where you want it. The same `insta` CLI, MCP server, and agent skill drive both the hosted service and [insta-oss](/self-hosting/install), the open-source runtime you can run on your own Docker.

## Start here

<Steps>
  <Step title="Install the CLI">
    <CodeGroup>

    ```bash npx
    npx insta@latest setup agent
    ```

    ```bash npm
    npm install -g insta
    ```

    ```bash title="Shell installer (macOS/Linux)"
    curl -fsSL https://agents.instacloud.com | sh
    ```

    </CodeGroup>

    The npx path also wires up any coding agents on your machine; npm installs just the CLI.
  </Step>
  <Step title="Deploy your app">
    From a directory with a Dockerfile:

    ```bash
    insta login
    insta project create my-app
    insta services add postgres db
    insta services add compute app
    insta secrets bind DATABASE_URL postgres/db --to compute/app
    insta deploy .
    ```

    That's a running app on its own URL, with its database connection injected.
  </Step>
  <Step title="Keep going">
    The [quickstart](/quickstart) walks through each step, including your first branch; [agent setup](/agents/setup) covers what the agent wiring installs.
  </Step>
</Steps>

## Hosted or self-hosted

| | InstaCloud | insta-oss |
| --- | --- | --- |
| Where it runs | Managed, multi-region | Your Docker |
| Accounts and billing | Yes | None — single tenant |
| CLI, MCP, skills | Same | Same |
| Cloud-only features | Orgs, GitHub deploys, custom domains, backups, usage | Returns `501` with guidance |

See [CLI & MCP compatibility](/self-hosting/compatibility) for the command-by-command list.
