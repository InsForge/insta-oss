---
title: "Governance"
description: "Every sensitive action passes an allow / deny / approve gate."
---

Every consequential operation — deploying, reading credentials, deleting things — is a named action with a policy decision: `allow`, `deny`, or `approve`. This is what makes it safe to hand a project to a coding agent: the agent can do everything you allow, nothing you deny, and must ask a human for anything you gate.

The mechanics work today:

```bash
insta policy get
insta policy set project.delete approve
insta approvals list
insta approvals approve <id>
insta approvals deny <id>
insta events
```

A gated action doesn't run — the caller gets an approval ID to relay, an admin decides, and grants are single-use. A token inherits its minter's role, so run agents under a member account, not an admin's, for approval to be a real gate. The [gated actions reference](/reference/gated-actions) has the full action table and a recommended baseline for agent access.
